29B. CSS GRID vs FLEXBOX (Kab Kya Use Hua?)
--------------------------------------------
Interviewer favorite question: "Flexbox aur Grid me kya fark hai aur kab kya use kiya?"

CSS GRID use hua hai MULTI-DIMENSIONAL LAYOUTS ke liye (rows + columns):

  .hero__grid           → 2 column split (text left, 3D right)
                           grid-template-columns: minmax(0, 1fr) minmax(330px, 0.82fr)
  .about__grid          → 2 column (photo left, text right)
                           grid-template-columns: 0.85fr 1.15fr
  .projects-grid        → 3 column card grid
  .skills-grid          → 3 column skill cards
  .education-grid       → 3 column education cards
  .certificates-grid    → 2 column cert cards
  .cert-tabs-grid       → 2 column tab buttons
  .footer__grid         → 3 column footer
                           grid-template-columns: 1.4fr 0.6fr 0.6fr
  .case-grid            → 4 column case study highlights
  .gallery-grid         → 2 column image gallery
  .modal-backdrop       → Centered modal container (place-items: center)
  .timeline-card        → Date + content split
                           grid-template-columns: 150px minmax(0, 1fr)

Total: 24 CSS Grid declarations in global.css

FLEXBOX use hua hai SINGLE-DIRECTION ALIGNMENT ke liye:

  .navbar               → Logo left, links right (justify-content: space-between)
  .navbar__links        → Navigation items inline
  .hero__actions        → Buttons side-by-side
  .hero__socials        → Social icons inline
  .certificate-controls → Search + dropdowns in 1 line
  .tech-list            → Technology badges wrap
  .terminal-card__bar   → Red/yellow/green traffic dots
  .skill-card           → Vertical stack (flex-direction: column)
  .certificate-row      → Row with title + buttons inline
  .lightbox-container   → Fullscreen image viewer

Total: 38 flex + 13 inline-flex declarations

SIMPLE RULE:
Grid = 2D layout (rows AND columns) = Page layouts, card grids
Flex = 1D layout (row OR column) = Navbar, buttons, badges, tags

30D. MAGNETIC CARD 3D TILT EFFECT (Custom Interactivity)
---------------------------------------------------------
File: frontend/src/components/common/MagneticCard.jsx

Ye ek custom interactive component hai jo mouse movement ke basis pe
cards ko 3D tilt effect deta hai.

WORKING:

1. useRef se card DOM element capture hota hai

2. onMouseMove pe:
   - getBoundingClientRect() se card ki position milti hai
   - Mouse ki X,Y position card ke relative calculate hoti hai
   - rotateY = ((x / width) - 0.5) * 6     (left-right tilt)
   - rotateX = ((y / height) - 0.5) * -6    (up-down tilt)
   - Transform apply:
     perspective(900px) rotateX(Xdeg) rotateY(Ydeg) translateY(-4px)

3. RESET triggers (tilt stuck na ho):
   - onMouseLeave → reset
   - onPointerLeave → reset (touch devices)
   - onClick → reset (link click pe)
   - onBlur → reset (focus lose pe)
   - window 'focus' event → reset (tab switch se wapas aane pe)
   - window 'visibilitychange' → reset (tab hide/show pe)

4. reset() function:
   card.style.transition = 'transform 0.3s ease-out';
   card.style.transform = 'perspective(900px) rotateX(0) rotateY(0) translateY(0)';

INTERVIEW ANSWER:
"MagneticCard me useRef se DOM access kiya, onMouseMove pe cursor
position ke basis pe rotateX/Y calculate karke 3D perspective transform
lagaya. 6 different event listeners pe reset karta hai taaki tilt
kabhi stuck na rahe."


30E. SMOOTH SCROLL / SCROLL-TO-TOP
------------------------------------
File: frontend/src/components/layout/SmoothScroll.jsx

Problem:
React Router me page change karne pe scroll position previous page ki
position pe reh jaati hai (browser default behavior).

Solution:
SmoothScroll component useLocation() hook se pathname track karta hai.
Jab pathname change hota hai, useEffect me window.scrollTo({top: 0})
call hota hai.

  const { pathname } = useLocation();
  useEffect(() => {

INTERVIEW ANSWER:

pathname change pe automatically page ko top pe smooth scroll karta hai.
Ye render kuch nahi karta, sirf useEffect side-effect run karta hai."

31. INJECTIONS - COMPLETE GUIDE (Security Interview Topic)
-----------------------------------------------------------
Interviewer: "Injection attacks kya hote hain aur kaise prevent kiye?"


31A. SQL INJECTION PREVENTION
-------------------------------
ATTACK: Hacker form me malicious SQL likhta hai:
  Name field: Robert'; DROP TABLE inquiries; --

VULNERABLE CODE (jo humne NAHI likha):
  db.run("INSERT INTO inquiries VALUES ('" + name + "')")
  → Ye directly SQL me name paste kar dega, table drop ho jayega!

SAFE CODE (jo humne USE kiya):
  db.run(
    "INSERT INTO inquiries (name, email, subject, message) VALUES (?, ?, ?, ?)",
    [name.trim(), email.trim().toLowerCase(), subject.trim(), message.trim()]
  );

? placeholders use kiye hain. SQLite driver VALUES ko automatically
escape/sanitize karta hai. Hacker chahe kuch bhi likhe, wo sirf
STRING data rahega, SQL command nahi banega.

INTERVIEW ANSWER:
"Parameterized queries (prepared statements) use kiye hain jisme
user input ? placeholder ke through pass hota hai. SQLite driver
automatically input ko escape karta hai, isliye SQL injection
possible nahi hai. Direct string concatenation avoid kiya hai."


31B. DEPENDENCY INJECTION (Backend Architecture Pattern)
---------------------------------------------------------
CONCEPT: Ek module doosre module ko directly create nahi karta,
balki bahar se inject (import) karke use karta hai.

Project me:

  db.js → Singleton database instance create karta hai
  inquiryModel.js → db.js se database import karke use karta hai
  inquiryController.js → inquiryModel.js se functions import karke use karta hai
  inquiryRoutes.js → controller functions ko routes me inject karta hai
  app.js → routes ko Express app me inject karta hai

  Flow:
  db.js → inquiryModel.js → inquiryController.js → inquiryRoutes.js → app.js

BENEFIT:
  - Database change karna ho (SQLite se PostgreSQL), sirf db.js change karo
  - Testing me mock database inject kar sakte ho
  - Loosely coupled architecture hai


31C. PROPS INJECTION (React Data Flow)
----------------------------------------
CONCEPT: Parent component child ko data props ke through inject karta hai.

Examples:

  <ProjectCard project={project} />
  → ProjectCard ko project object inject hua

  <Navbar theme={theme} onToggleTheme={toggleFn} />
  → Navbar ko current theme aur toggle function inject hua

  <CertificateCard cert={cert} onView={handleView} />
  → CertificateCard ko certificate data aur view handler inject hua

Theme injection:
  document.documentElement.setAttribute('data-theme', theme)
  → HTML root element pe theme attribute inject hota hai
  → CSS variables automatically switch ho jaate hain

INTERVIEW ANSWER:
"React me data top-down flow karta hai parent se child tak props ke
through. Ye unidirectional data flow hai. Theme injection HTML root
attribute pe setAttribute se hota hai jisse CSS variables toggle hote hain."


31D. XSS (Cross-Site Scripting) PREVENTION
--------------------------------------------
ATTACK: Hacker form me malicious script likhta hai:
  Message: <script>document.cookie</script>

PREVENTION LAYERS:

1. FRONTEND: React by default JSX me text ko escape karta hai.
   {userInput} render karne pe React HTML entities me convert kar deta hai.
   <script> tag render nahi hoga, plain text dikhega.

2. BACKEND VALIDATION: validateInquiry middleware fields validate karta hai.
   Empty ya malicious input reject hota hai.

3. DATABASE: Parameterized queries se data safely store hota hai.

4. API RESPONSE: Express ka res.json() automatically JSON escape karta hai.

INTERVIEW ANSWER:
"React JSX by default XSS prevent karta hai kyunki curly braces me
text automatically HTML escaped hota hai. Backend pe input validation
middleware hai aur parameterized SQL queries se data safely store hota hai."

32B. CORS (Cross-Origin Resource Sharing)
-------------------------------------------
PROBLEM: Browser by default different origin (domain) se API call block karta hai.
Frontend (localhost:5173) se Backend (localhost:5000) different origins hain.

SOLUTION:
  cors({
    origin: env.nodeEnv === 'production' ? env.frontendOrigin : true,
    methods: ['GET', 'POST'],
    allowedHeaders: ['Content-Type', 'x-admin-token']
  })

Development me: origin: true (sab allow)
Production me: origin: env.frontendOrigin (sirf portfolio site allow)

INTERVIEW ANSWER:
"CORS middleware configure kiya hai. Production me sirf frontend
domain allowed hai, development me sab origins allow hain. Sirf
GET aur POST methods allowed hain. x-admin-token header admin
endpoints ke liye use hota hai."


32C. PAYLOAD SIZE LIMIT (DoS Prevention)
------------------------------------------
  express.json({ limit: '1mb' })

Agar koi hacker 100MB ka JSON body bheje to server crash ho sakta hai.
1MB limit lagayi hai taaki oversized payloads reject ho jayein.


32D. SINGLETON DATABASE PATTERN (db.js)
-----------------------------------------
  let database;    ← Module-scoped variable

  export async function getDatabase() {
    if (database) return database;    ← Already open? Return cached
    database = await open({...});     ← First time? Open and cache
    await database.exec('PRAGMA foreign_keys = ON;');
    return database;
  }

BENEFIT:
  - Har request pe new connection nahi khulta (performance)
  - Ek hi connection reuse hota hai (resource efficient)
  - Foreign keys enforce hote hain (data integrity)

INTERVIEW ANSWER:
"Singleton pattern use kiya hai database connection ke liye. Module-scope
variable me cache karta hai. Pehli baar call pe connection open hota hai,
baad me same cached connection return hota hai. Ye connection pooling
ka simple version hai."
